# PQL-011: C++ PostgreSQL persistence

Hypothesis: shared transactional repository access can persist financial events
without duplicating business rules or permitting partial financial commits.

Problem: the domain and schema exist, but no C++ adapter connects them.

Learning objective: use RAII for transaction ownership; distinguish a row write
from an atomic financial operation; make decimal conversion policy explicit.

Generation target: three interfaces, one libpqxx unit of work, typed observations,
append/replay, portfolio metadata updates, and disposable database integration tests.

Resolution signal: real PostgreSQL insert/read/rename/rollback tests pass, including
cross-connection replay, competing purchases, precision rejection and mid-append
failure without orphan rows.

Constraints: C++20, existing domain invariants and schema, immutable transactions,
no SQL in domain logic, no strategy mutation authority, no ORM/pool/new infrastructure.

Unknowns resolved: Debian libpqxx discovery needs pkg-config fallback; embedded NUL
text must reject before binding; canonical decimal comparison can preserve engine
round trips and reject precision-losing imported NUMERIC values.

Deferred: native Windows libpqxx linking, connection-loss/uncertain-commit fault
injection, projection persistence, market revision workflow and strategy attribution.
