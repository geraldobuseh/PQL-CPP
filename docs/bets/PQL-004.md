# PQL-004: Financial primitive types

## Bet and resolution signal

Private storage and distinct C++ types can prevent accidental domain substitution
without a generic type framework. Success means all eight types compile, cross-type
construction/assignment is rejected at compile time, and invalid primitive inputs
are rejected by deterministic unit tests.

The learning objective is to distinguish a type alias from a domain type: an alias
only renames a representation; a class creates a separate compiler-enforced boundary.

## Contract

Include `domain/financial_types.hpp` and link the `pql_domain` CMake target. All
types live in namespace `pql`. They have value semantics, private storage, read-only
`value()` access and exact same-type equality. There are no implicit conversions,
default constructors, setters or financial arithmetic operators.

| Type | Representation and valid values |
| --- | --- |
| `Symbol` | Owned string matching `[A-Za-z0-9][A-Za-z0-9.-]*`; case preserved |
| `Money` | Finite `double`, including negative amounts and zero |
| `Quantity` | Finite nonnegative `double` magnitude, including fractional units |
| `Price` | Finite strictly positive `double` equity quote |
| `Timestamp` | `std::chrono::sys_time<std::chrono::milliseconds>` instant |
| `OrderId` | Positive `std::int64_t` |
| `PortfolioId` | Positive `std::int64_t`, distinct from the other ID classes |
| `StrategyId` | Positive `std::int64_t`, distinct from the other ID classes |

Validated types expose `create(value) -> std::optional<Type>`. Rejection returns
`std::nullopt`; callers must check before dereferencing. This makes invalid input
an ordinary result rather than exception-based control flow. Allocation failures
for owned strings can still throw. Timestamp uses an explicit constructor because
every representable instant is valid, including epoch, pre-epoch and future values.
It supports chronological comparisons and never reads the wall clock.

```cpp
const auto symbol = pql::Symbol::create("SPY");
const auto quantity = pql::Quantity::create(0.5);
const auto portfolio = pql::PortfolioId::create(1);
// Check optional results before using them.
// pql::StrategyId strategy = *portfolio;  // compile error: different domain
```

Symbol copies even from rvalues so the source remains a valid, nonempty symbol.
Inputs are owned and never trimmed or uppercased. The symbol grammar is a local
contract, not proof that a symbol exists at an exchange.

## Constraints and unknowns

This is a representation boundary, not an accounting or trading implementation.
`double` remains approximate; equality is exact stored-value equality. Money and
price assume one externally agreed currency. Currency representation, rounding and
exact decimal accounting require future decisions. Quantity is not a signed position
or trade delta, and Price is not a zero-valued holding valuation or a generic price
for instruments that permit negative quotes.

Factories accept typed primitive parameters; parsing and range checking before
numeric conversion remain the responsibility of future ingestion/API boundaries.
ID uniqueness and generation, exchange-specific symbols, timestamp parsing, market
calendars and data freshness checks are outside this ticket. No persistence, API or
financial fields exist yet to migrate. No strategy benchmark is applicable.

## Validation

`test/test_financial_types.cpp` checks all ordered pairs of domain types at compile
time, primitive conversion boundaries and lack of default/aggregate construction.
Runtime cases cover symbol ownership and malformed inputs, copy/move invariants,
NaN/infinities, signed money, fractional/zero quantities, positive prices, signed
64-bit ID boundaries, equality and deterministic timestamps around the epoch.

Independent architecture, quant, validation and C++ review evidence is recorded in
`.codex/reviews/PQL-004/`.
