# PQL-012: market-data provider boundary

Hypothesis: a small abstract interface lets the engine consume prices without
depending on vendor SDKs or persistence details.

Problem: the engine needs a replaceable source of latest prices and history.
Learning objective: use runtime polymorphism at an actual substitution boundary.
Generation target: exact requested MarketDataProvider methods, Date/PriceBar values,
contract documentation and synthetic tests.

Constraints: C++20, existing validated financial primitives, no external adapter or
new dependency. Resolution signal: exact signature assertions, polymorphic consumer
tests and domain edge cases compile and pass alongside the existing suites.

Unknowns bounded by contract: calendar/session labels, inclusive ranges, missing
observations, errors, raw-price treatment and point-in-time availability. Real
provider behavior and future backtest availability gating remain separate work.
