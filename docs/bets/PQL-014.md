# PQL-014: real daily market data

Hypothesis: one isolated HTTP adapter and atomic insert-or-compare storage can ingest
real daily prices repeatably without duplicate rows or silent financial revisions.

Problem: fake fixtures cannot supply actual SPY/QQQ/AAPL/MSFT/NVDA/AMZN/GOOGL/META data.
Learning objective: provider validation, retry classification, durable identity and
observable failure boundaries. Generation target: Alpha Vantage adapter, daily
session migration, repository ingestion operation, CLI and fixture/integration tests.

Resolution signal: all symbols decode; repeat/concurrent imports retain one row per
identity; conflicting revisions roll back; HTTP failures retry only as classified;
live data can be fetched and stored using local credentials.

Constraints: raw dailyUSD data, existing domain/SQL separation, no secrets in logs,
no network in core tests, no framework/queue/scheduler/extra infrastructure.

Unknowns bounded explicitly: compact coverage, account quotas, excluded current-day
bars, no independent calendar-hole detection or point-in-time availability guarantee.
Confirmed numeric-format mismatch was resolved by sharing the persistence canonical
decimal representation at parse validation. Migration upgrades now pin search_path.
