# PQL-015: actionable market-data validation

Hypothesis: rejecting invalid provider responses with stable issue codes and safe
context makes data quality failures actionable before portfolio logic consumes them.

Problem: existing rejection checks mostly report a generic malformed response.
Learning objective: distinguish structurally valid data from trustworthy investment
inputs. Generation target: typed validation errors, provider classification, CLI
diagnostics, synthetic regression tests and notes/005-data-quality.md.

Resolution signal: each required invalid condition rejects with identifiable
context, no invalid response exposes a valid prefix to storage, and existing
ingestion and portfolio suites remain green.

Constraints: retain provider interface, whole-response validation, canonical numeric
checks, idempotent storage and safe logs. No new infrastructure or live API calls.

Unknowns: structural checks cannot establish quote accuracy, exchange-session
completeness, freshness, corporate-action correctness or historical availability.
Those controls remain separate work.
